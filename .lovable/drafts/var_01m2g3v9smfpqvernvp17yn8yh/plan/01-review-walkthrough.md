# Review the draft in the preview before accepting

A guided pass through the three changes in this draft. Nothing here is destructive — you're just looking. When you're satisfied, say "accept the draft" (or use the **Accept draft** button top-right on desktop).

## 1. Unit number pool

1. Go to the Vehicle Hub (Equipment section → Vehicle Hub). You are already there.
2. Click **Unit Numbers** next to the search box.
3. Expected now: lookup field pinned at top, then the message that the list turns on when the draft is accepted. This message is the proof the wiring works; the real numbers require the database change that only lands on accept.
4. Then open the Onboarding Pipeline, pick any in-progress driver, and open the unit-number field. Expected: the picker opens with the same friendly message; you can still type a number by hand.

## 2. Applications page — screening and interviews

1. Management portal → Applications.
2. Look at the column headers: **Applied** (renamed from Submitted, fixes the overlap) and **Screening**.
3. In the Screening column, each application shows three small chips: **MVR**, **PSP**, **CH**. They are label-only (no dots or checks) and should sit on one row. Colors carry the status; hover a chip (tap and hold on mobile) for the full status and the request/receive dates.
4. In the Interview column, expand one row's interview notes: the panel opens; only one application's notes can be expanded at a time. Notes are staff-only and hidden from printing.
5. Open one application's review drawer → Background Verification section. **PSP sits between MVR and Clearinghouse** with the same dropdown options and the same request/receive date fields.

## 3. What to keep in mind

- Approving an application now requires MVR + PSP + CH all received — but only for applications approved from now on. Already-approved and onboarded drivers are untouched.
- Interview notes and PSP values can't be fully saved until the draft is accepted, because the storage for them is created on accept. If you try to add a note and it fails, that is expected pre-accept behavior.
- If anything looks wrong during this review, tell me what you saw and where, and I'll fix it before you accept.
