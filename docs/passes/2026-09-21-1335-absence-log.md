## What the pass built

Dispatch can now record WHY a driver is off the road against a DATE, and read it
back as a time log. The free-text Notes box that held one sentence per driver —
overwritten every time it changed, with no history — is gone from both views.

The name chosen with the owner: **Absence Log**.

### Schema — STAGED, not applied

`.lovable/drafts/var_01m31zfbdhe9faa5va8k1a0xnh/migrations/20260921130000_absence_log_reasons.sql`,
additive only, applied the moment this draft is accepted:

- `absence_reason` enum: `truck_down`, `home_time`, `vacation`, `medical`,
  `personal`, `waiting_on_load`, `no_driver`, `other`.
- `dispatch_daily_log.absence_reason` (null on a dispatched day), `notes_by`,
  `notes_at`, plus an index on `(operator_id, log_date DESC)`.
- The table's existing `notes` column (6,039 rows, every one NULL) is reused for
  the free-text note rather than a new column.
- `notes_by` carries NO foreign key: the table's existing `created_by` holds an
  **auth user id**, not a `profiles.id`, so a FK to `profiles` would be wrong.
  Names are resolved in the page from the staff map it already loads.
- RLS and grants on `dispatch_daily_log` already cover new columns; nothing was
  widened.

### Code

- `src/lib/absenceLog.ts` — reason list and labels, `canSaveAbsence` (Other must
  carry a note), `groupAbsenceStretches` (consecutive same-reason days collapse; a
  gap or a change of reason starts a new stretch), `summarizeAbsence`,
  `resolveRange`, `formatStretchDates`. Pure, no I/O.
- `src/components/dispatch/AbsenceLogPanel.tsx` — range preset (this month /
  quarter / year / all time / custom from–to), a one-line total, and the
  chronological list of stretches with reason, note and who entered it.
- `src/components/dispatch/MiniDispatchCalendar.tsx` — the day popover now takes
  status + reason + note; the Range tool takes the same pair, so a whole week is
  one entry. Today's entry still syncs to `active_dispatch` (writing
  `"<Reason> — <note>"` into `status_notes`, which the truck-down toast, the
  status-history timeline and the history download all read) and still writes a
  `dispatch_status_history` row when the day is today.
- `src/pages/dispatch/DispatchPortal.tsx` — cards: the History dropdown below the
  calendar is now the Absence Log dropdown, and the Notes box (view and edit) is
  gone. Table: the History button under the name opens the same panel, and the
  Notes column and its header are removed (colSpans adjusted 7/6 → 6/5). A
  per-operator refresh counter re-reads the open log after the calendar writes.

### One guard amended, deliberately

`src/lib/__tests__/postgrestEmbeds.test.ts` verifies every `.select()` against
the GENERATED types, which are only regenerated when a draft is accepted. Two
selects reading the staged `absence_reason` were therefore reported as broken
requests. Rather than allowlist two line numbers, the schema loader now also
reads `ADD COLUMN` out of staged draft migrations, so the allowance covers any
staged column and disappears on its own once the types catch up. The guard still
fails on a column that exists nowhere — verified by the 3,912 references it
checks.

## Not in scope

stays in the database — three readers depend on it.
