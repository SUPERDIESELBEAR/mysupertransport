## STEP 1 — THE FOUNDATION

Built exactly as designed:

- `permission_actions` — `key` PK, label, description, category, `kind`
  (`permission_kind`: view/change), `is_active`. **No `company_id`**: the set of
  actions SUPERDRIVE can enforce is decided by the code that enforces them, never
  by a carrier. RLS on, SELECT to `authenticated`, **no write policy at all**;
  rows arrive by migration.
- `role_permissions` — `company_id` → `carrier_profile` ON DELETE RESTRICT, `role`
  (`app_role`), `action_key` → `permission_actions`, UNIQUE(company_id, role,
  action_key). Presence of the row **is** the grant. `aa_stamp_tenant_company_id`
  trigger, RESTRICTIVE `tenant_isolation`, staff READ, **owner-only WRITE via
  `has_role`, never via a permission** — so no grant can lock the owner out of
  fixing grants.
- `user_permission_exceptions` — same tenancy furniture, plus `user_id`, `effect`
  (`permission_effect`: allow/deny), nullable `expires_at`, `reason NOT NULL`,
  UNIQUE(company_id, user_id, action_key).
- `has_permission(_user_id uuid, _action text)` and `has_permission(_action text)`
  — STABLE, SECURITY DEFINER, `SET search_path = public, extensions`, EXECUTE
  revoked from PUBLIC and anon, granted to `authenticated` and `service_role`.
  Resolution order: NULL user → false; **unknown key → RAISE 22023**; **owner
  short-circuit before any table is read**; `current_company_id()` NULL → false;
  own unexpired exception wins either way; otherwise `user_roles ⨝
  role_permissions`. A known key with no grant is **closed**.
- Both signatures registered in `definer-live-catalog.test.ts` with
  `KNOWN_AUTHENTICATED_EXECUTABLE_MAX` 133 → 135 and the reason recorded.
  `seed_role_permissions(uuid)` is service_role only and therefore not in that
  registry — that is what stops a signed-in user handing a carrier fresh grants.

Undo for the whole pass is written as a comment at the head of the migration.

| `invoice.view` | yes | yes | — |

The owner appears nowhere in those rows on purpose: P1 lives in the function.

- **(a) Lease terminations.** `"Staff manage lease terminations"` (one FOR ALL
  policy on `is_staff()`, i.e. any staff role could terminate a lease) dropped,
  replaced by `lease_terminations_view` (SELECT) and `lease_terminations_change`
  (ALL, with WITH CHECK). The pre-existing `Operators view own terminations`
  policy and `tenant_isolation` were left untouched.
- **(b) Company documents.** `document_send_log_insert_staff` (four staff roles)
  dropped, replaced by `document_send_log_insert_permission` gated on
  `company_document.send`. `company_documents` SELECT was left exactly as it is.
- **(c) Settlement and invoice view.** Three purely additive SELECT policies on
  `settlements`, `dispatch_settlements` and `invoices`. The management FOR ALL
  policies and the operators' own-row policies are unchanged.

### DEPARTURE FROM THE DESIGN — reported, not worked around

The prompt's Step 3(b) asks for "the sending edge function calling the
two-argument form". **There is no such function.** `document_send_log` is
referenced only in generated types and one test; no edge function and no screen
sends a company document today, `document_send_log` holds 0 rows, and
`company_documents` holds 0 rows. The database half of P7 is now enforced and
will be in force the day a sender is written; **no edge function was changed and
none deployed.** This gap was reported before building rather than papered over
by inventing a sender.
